# VALORANT 戦績サイト

自分の VALORANT の試合を取り込み、HS%・FB・FD などを集計して表示する個人用サイト。
Cloudflare Workers + D1 で動き、データは [HenrikDev API](https://docs.henrikdev.xyz/)（非公式）から取得する。

## 見られるもの

- **概要**: 勝率、K/D、ACS、ADR、HS%、KAST、FB / FD（回数と、その時のラウンド勝率）、試合ごとの推移、ランク推移
- **内訳**: 命中部位、攻守別、ピストルラウンド、マルチキル、クラッチ、トレード、設置 / 解除
- **切り口別**: エージェント別、マップ別、武器別キル、一緒に遊んだ人ごとの勝率
- **試合一覧と試合詳細**: 全10人のスコアボードと、ラウンドごとのキルの流れ
- モード、アクト、エージェント、マップ、直近N試合で絞り込み

## トップページとプレイヤーの検索

サイトを開くとトップページが表示される。検索欄に Riot ID（`名前#タグ`）を入れると、その人の戦績ページ（`#/player/<ID>`）が開く。試合詳細のスコアボードやチーム分けの一覧にある名前からも移動できる。

検索済みのプレイヤーの一覧は、画面にも API にも出さない（誰を検索したかを他の閲覧者に見せないため）。もう一度見るときは、Riot ID で検索し直すか、その人のページの URL を開く。

`RIOT_IDS` に書いた本人も、扱いは検索した人と同じ。違いは取り込みの範囲だけで、本人は全履歴を取り込み、生データも保存する。

- 一度検索した人は保存され、次回からは保存済みのデータをすぐ表示して、新しい試合だけ取り込む
- 初回は直近40試合まで（デスマッチなどラウンド制でないモードは除く）を取り込む。ページを開いている間は数秒おきに進み、取り込めた分から表示される
- 新着の確認は、そのページを開いたとき（5分に1回まで）と、直近14日以内に見られた人について2時間おき
- 容量を抑えるため、検索された人の試合は集計結果だけを保存する（1試合あたり約15KB）。本人（`RIOT_IDS`）の試合は生データも保存する（1試合あたり約300〜400KB）
- 公開サイトなので、Riot ID の検索は10分に40回まで、検索で登録できるのは300人まで

## 指標の定義

| 指標 | 定義 |
|---|---|
| HS% | 命中した弾のうち頭に当たった割合（頭 ÷ 頭+胴+脚） |
| ACS | 戦闘スコア ÷ ラウンド数 |
| ADR | 与ダメージ ÷ ラウンド数。ダメージが記録されていない試合（カスタムなど）は分子にも分母にも入れない |
| FB / FD | 各ラウンドで最初に「敵を倒した」キルの、倒した側 / 倒された側。落下死やスパイクでの自滅は含めない |
| KAST | キル・アシスト・生存・トレードされたデスのいずれかがあったラウンドの割合 |
| トレード | 味方を倒した敵を 5 秒以内に倒すこと（`src/stats.ts` の `TRADE_WINDOW_MS`） |
| クラッチ | チームで最後の1人になった時点で敵が1人以上残っていて、そのラウンドに勝つこと。蘇生は考慮しない |

## モードの扱い

- 集計はモードごとに分かれる。初期表示はコンペティティブ
- 「通常マッチの合計（カスタムを除く）」は、5対5 の通常マッチ（コンペ、アンレート、Premier、スイフトプレイ）の合算
- カスタムは内容で2つに分け、選んだときだけ表示する
  - **カスタム（5vs5）**: 通常ルール（爆破）で 5対5 の試合。ダメージや命中部位も記録されるので、全ての指標が出る
  - **カスタム（その他）**: スカーミッシュ、デスマッチ、少人数や人数差のある試合など。スカーミッシュは API がダメージと命中部位を返さないため、ADR と HS% は出せない
- スカーミッシュ（2対2）やデスマッチなどは、そのモードを選んだときだけ表示する。ラウンド制でないモードは K/D など一部の指標だけ

## 仕組み

- 10分おきの定期実行が、新しい試合IDを検出してキューに積み、1回につき2試合ずつ取り込む
- 初回は Riot の試合履歴と HenrikDev 側の保存済み試合から、取れるだけ過去に遡る
- 本人の試合は生データも D1 に保存するので、指標の定義を変えても作り直せる
- テーブルは起動時にコードが自動作成する（マイグレーションの手動実行は不要）

## チーム分け

カスタムの参加者を、レートとロールが釣り合うように2チームに分ける。サイトの「チーム分け」タブと Discord bot のどちらからでも使え、登録したプレイヤーは共通。

### ウェブ

サイトの **チーム分け** タブで使う。追加の設定は不要。

- Riot ID（`名前#タグ`）を入力して追加すると、現在のランクを取得して一覧に入る
- 複数人をまとめて追加できる。改行かカンマで区切って貼り付ける（一度に20人まで。Enter で追加、Shift+Enter で改行）。新規の人は API の回数制限に収めるため6秒おきに1人ずつ処理し、見つからなかった ID は一覧で示す
- 一覧から参加者を選ぶ（最大10人）。Riot ID を使わない人は「ゲスト」として名前・ランク・ロールを手入力できる
- 「チーム分けする」で分け、「振り直し」「マップ変更」「攻守を入れ替え」「結果をコピー」ができる
- 選択とゲストはブラウザに保存される（他の人の画面とは共有されない）

公開サイトなので、Riot ID の検索は10分に40回まで（戦績の検索と共通）、ウェブから追加できるのは60人までに制限している。ウェブから追加した人は誰でも一覧から削除できる。

### Discord bot

常駐プロセスは不要で、サイトと同じ Worker の中で動く。

| コマンド | 内容 |
|---|---|
| `/link riot_id:名前#タグ` | 自分の Riot ID を登録する。参加に必要 |
| `/unlink` | 登録を解除する |
| `/rating` | チーム分けに使われる自分のレートと内訳を見る |
| `/custom` | 募集メッセージを出す。「参加」「抜ける」「チーム分け」のボタンが付く |

チーム分け後は「振り直し」（次に釣り合う案へ）、「マップ変更」、「募集に戻る」ができる。

### レートの決め方

**レート = ランク由来の土台 + 直近の成績による補正**

- **土台**: 現在のランクを、過去の実績の側へ寄せた値
  - 現在のランクは 1段階 = 100 として RR を足す（プラチナ1・23RR = 1223）
  - 過去の実績は、アクトごとの到達ランク（最終ランクとアクトランクの高い方。10試合以上遊んだアクトだけ）と生涯最高ランクから求める。半年（3アクト）以内はそのまま、それより古いものは1アクトごとに25点割り引き（上限300点）、その中で一番高い値を取る
  - 現在のランクが実績より低いときは、差の 40〜75% を実績の側へ寄せる。今のアクトの試合数が少ないほど大きく寄せる（10試合以下で75%、50試合以上で40%）
- **現在ランクがない人**は、手がかりに応じて3通りに分ける
  - 過去にランクがあった人（休止・引退）: 過去の実績から50点引いた値
  - ランクの記録が一切ない人: アカウントレベルから決める（150 + レベル × 5、下限200・上限900）。レベル23なら265で、始めたばかりの人として扱う。レベルが高ければ、ランクを回していない経験者として高めに置く
  - レベルも取得できなかった人: その回の参加者の平均
- **補正**: 直近の成績（取り込み済みの直近20試合。コンペ・アンレート・Premier、120日以内）
  - 1試合ごとに「自分の ACS ÷ その試合の10人の平均 ACS」を出し、ロールごとの平均（デュエリスト 1.11、コントローラー 0.99、センチネル 0.96、イニシエーター 0.90）で割って均す
  - それを「土台のレートの人が、その試合のランク帯で出すはずの成績」と比べる。格下相手に稼いだぶんは補正に入らない
  - 差を点数に直して平均し、試合数に応じて弱める（n 試合なら n ÷ (n + 8) 倍）。上限は ±300
- **ロール**: 同じ試合群で一番多く使ったエージェントのロール

### チームの分け方

レートをそのまま足すのではなく、その場の平均からの離れ具合を「戦力」に直してから比べる。平均の近くではレート差どおりだが、平均より 350点以上低い人は差の 2.5倍、250点以上高い人は 1.3倍効くものとして扱う（極端に差がある人は、レート差以上に試合へ影響するため）。

全ての分け方を調べ、「戦力の合計の差 + ロールの偏り1人につき25点」が最小の案を選ぶ。奇数人数のときは人数の少ない側に強い人が寄る。

ロールごとの平均や効き方の数字は、コンペ84試合・のべ840人分の実測値から決めた。データが増えたら見直す。

例: 4アクト前にイモータル1（実績 2075）で、現在ダイヤ2・50RR（1650）、今アクト30試合の人は、土台が 1894 になり、アセンダント1（1800〜1899）の上位と同じ扱いになる。

土台の定数は `src/skill.ts`、補正と戦力の定数は `src/balance.ts`、エージェントとロールの対応は `src/agents.ts` にある。対応表にないエージェントは「ロール不明」として扱われる。

登録した人（ウェブ・Discord とも）の試合は、1人あたり1時間以上の間隔で新着を確認して取り込む。登録直後は補正とロールが無く、取り込みが進むと反映される。

### Discord bot のセットアップ

1. [Discord Developer Portal](https://discord.com/developers/applications) で **New Application** を作る
2. **General Information** の Application ID と Public Key、**Bot** タブの Token（Reset Token で発行）を控える
3. Cloudflare の Worker の **Settings → Variables and Secrets** に、種類 Secret で3つ追加する
   - `DISCORD_APP_ID`、`DISCORD_PUBLIC_KEY`、`DISCORD_BOT_TOKEN`
4. Developer Portal の **General Information → Interactions Endpoint URL** に `https://<サイトのドメイン>/api/discord` を入れて保存する
   - 保存時に Discord が疎通確認を送り、その時にスラッシュコマンドが自動登録される
5. **Installation** タブで Guild Install のスコープを `applications.commands` にし、表示される Install Link からサーバーに追加する

### うまくいかないとき

ブラウザで `https://<サイトのドメイン>/api/discord` を開くと、3つの値が設定されているか・形式が合っているか、スラッシュコマンドが登録できたかが表示される（値そのものは表示されない）。

- 「未設定」と出る: Secret を追加したあと Deploy を押していないか、変数名が違う
- このページ自体が開けない、ログイン画面になる: Cloudflare Access などでサイト全体に制限がかかっている。Discord からのアクセスも止められるので、`/api/discord` を制限の対象から外す
- 設定は全部 OK なのに Discord 側で URL を保存できない: Cloudflare のボット対策（Bot Fight Mode など）が Discord からのアクセスを止めている可能性がある。ドメインの Security 設定で無効にするか、Interactions Endpoint URL に Worker の `*.workers.dev` の URL を使う

### 注意

- `/link` もウェブからの追加も、Riot ID の持ち主かどうかは確認しない（確認には Riot の公式ログイン連携が必要）。身内向けの作り
- VC への自動振り分けは未対応

## デプロイ（Cloudflare）

1. Cloudflare ダッシュボードの **Workers & Pages → Create → Import a repository** でこのリポジトリを選ぶ
   - Build command は空、Deploy command は `npx wrangler deploy` のまま
   - D1 データベースは初回デプロイ時に自動で作られる
2. 作成された Worker の **Settings → Variables and Secrets** に、種類 **Secret** で `HENRIK_API_KEY` を追加する（HenrikDev の APIキー）
3. **Settings → Domains & Routes** でカスタムドメイン（例 `val.example.com`）を割り当てる
4. サイトを開くと初回の取り込みが始まる

追跡する Riot ID は `wrangler.jsonc` の `RIOT_IDS`（カンマ区切りで複数可）。

自分だけに見せたい場合は、Cloudflare Zero Trust の Access でそのドメインにログイン制限をかける。

## ローカル開発

```bash
npm install
echo 'HENRIK_API_KEY=HDEV-xxxx' > .dev.vars   # コミットしない
npm run sync:local                            # 実データをローカル D1 に取り込む
npm run dev                                   # http://localhost:8787
npm test                                      # 指標計算とチーム分けの単体テスト
npm run sync:local -- --recompute             # 保存済みの生データから再集計
```

## 制約

- HenrikDev API は非公式。仕様変更や停止で取得できなくなる可能性がある
- 無料キーは 30 リクエスト/分。初回の取り込みは数分かかる
- 過去の試合は API 側に残っている分しか取れない。取り込み開始以降の試合は欠けずに貯まる
- ランク推移は API が返す直近分から貯め始める
- D1 の容量には上限がある（無料プランは1データベース 500MB のはず）。本人の試合を生データ付きで貯めると、1000試合で 300〜400MB になる
- Cloudflare 無料プランは1回の実行あたりの CPU 時間が短い。取り込みで CPU 制限のエラーが続く場合は Workers 有料プランが必要

このサイトは Riot Games の承認・後援を受けたものではありません。
