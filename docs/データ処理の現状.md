# データ処理の現状（2026-11-24 時点）

本番（Cloudflare Workers + D1 + R2）で、いつ・何が動き、D1 をどれだけ使っているかをまとめたもの。
数字は本番の D1 に実際に問い合わせて測った値（読み取り行数）と、同じエンジンのローカル D1 で測った値（書き込み行数）。

## 0. 読み取りの上限に毎日達していた原因と対応（2026-11-24 追記）

D1 の読み取り（1日500万行）に毎日達していた。原因は定期実行ではなく、ブラウザ側の処理だった。

- **原因**: 本人アカウント（`RIOT_IDS` に書いた人）のページを開くと、ブラウザが「サイト全体の取り込み待ちが0になるまで」5秒おきに同期と画面の描き直しを繰り返していた（最大150回、約12分半）。収集対象の取り込みを始めてからは全体の待ちが常に残るので、ページを開くたびに150回まわり切っていた。
- **1回あたり**: 同期・概要・試合一覧・ランク推移で約4,000〜8,000行。1度ページを開くだけで60万〜120万行を読む。数回開けば上限に届く。
- **対応**: 待つのは「いま開いている人の試合」だけにした。描き直しも、その人の待ちが減ったときだけ。あわせて、同期状況の取得（1回約5,900行 → 数十行）、チーム分けの一覧（約9,000行 → 数行）、古い試合の削除の候補探し、圧縮待ちの検索を、表を全部読まない形に直した。本人アカウントの RR 履歴も、新しい行だけ書くようにした（書き込みが1日約2万行減る）。

- **さらに（同日）**: 画面からの自動の同期をやめた。ページを開いただけ・開いたままでは同期も再取得もせず、右上の「更新」を押したときと、Riot ID を検索した直後にだけ動く。チーム分けタブの15秒おきの確認もやめ、「更新」で取り直す形にした。

以下の 2〜5 章の行数は、この対応より前の値。対応後の値は次のとおり。

| 処理 | 対応前 | 対応後 |
|---|---|---|
| 本人のページを開く（取り込み待ちが全体にある日） | 60万〜120万行 | 約1万行 |
| 同期状況の取得（`/api/status`） | 約5,900行 | 取り込み待ちの件数ぶん（ふだんは数十行） |
| チーム分けの一覧・分ける | 約9,000行＋1人約200行 | 数行＋1人約200行（最近のマップは6時間おきに約2,500行で作り直す） |
| 古い試合の削除の候補探し（1時間に1回） | 約4,200行 | 14日より古い試合のぶんだけ |
| 圧縮待ちの生データの検索（5分ごと） | 153行 | 0行（待ちがないとき） |
| 本人アカウントの RR 履歴（書き込み） | 1日約20,000行 | 新しい試合のぶんだけ |

## 2. 定期実行

Cloudflare の定期実行は毎分動く。中身は3段階。

### 毎分

1. チーム分けに登録した人の試合が取り込み待ちに残っているか数える（読み取り 2行）。
2. 残っていれば「急ぎの取り込み」: その試合だけを API の枠いっぱい（1分15試合）まで取り込む。1回2試合の処理を、Worker が自分自身を呼び直して繰り返す。最後の登録から20秒は始めない。
3. 残っていなければ、5分に1回だけ下の「通常の同期」を回す。それ以外の分は何もしない。

### 5分ごと（通常の同期）

| 順 | 処理 | 内容 | D1 読み取り | D1 書き込み |
|---|---|---|---|---|
| 1 | 本人アカウントの確認 | 8アカウントのうち、確認が古い順に最大3つ。試合履歴20件と RR 履歴を取り、未取得の試合を取り込み待ちに積む | 約35行／人 | RR 履歴の上書きで約23行／人（内容が変わっていなくても毎回書く） |
| 2 | 検索された人の確認 | 14日以内に見られた人を、2時間以上あけて最大2人 | 少量 | 少量 |
| 3 | 登録者の確認 | 1時間以上あけて最大2人。直近10試合を積み、ランクを取り直す。RR 履歴は12時間に1回 | 少量 | 1〜3行／人 |
| 4 | 失敗した試合のやり直し | API 側の一時的な障害で諦めた試合を、3時間後に取り込み待ちへ戻す | 1〜2行 | 該当があれば1行 |
| 5 | 収集対象の確認 | 141人のうち、確認が古い順に2人（1人あたり約6時間おき）。直近20試合からデスマッチなどを除いて積む | 約30行 | 2行／人＋新しい試合1件につき約4行 |
| 6 | 試合の取り込み | 取り込み待ちから2試合。順番は、開いている人 → 登録者 → 本人 → カスタム → 新しい順 | 約15行／試合 | 46行／試合 |
| 7 | 保管庫への書き出し | まだ書き出していない試合を最大20件、R2 へ。1日1回、登録者と本人の状態の控えも書く | 約20行＋試合ぶん | 2行／試合 |
| 8 | 収集対象の自動追加 | 試合を取り込んだ回だけ。本人や登録者が出た 5vs5 カスタムの参加者を加える（上限400人） | 約50行 | 追加があれば |
| 9 | 古い試合の削除 | 1時間に1回、最大40試合。収集対象だけの試合で、試合の日から14日たち、R2 へ書き出し済みのもの | 約4,200行（試合の一覧を全部見る） | 11行／試合 |
| 10 | 生データの圧縮 | 試合を取り込まなかった回だけ、未圧縮の生データを2件 gzip にする | 153行（生データの一覧を全部見る） | 2行／件 |

1試合の取り込みで書く46行の内訳は、試合1行、10人ぶんの成績10行、それぞれの索引、取り込み待ちの更新。

### 1日あたりの量（いまの実績）

- 取り込む試合: 220〜300件（収集対象ぶんが大半）。上限は「5分に2試合」で1日576件。
- 保管庫（R2）へ書き出す試合: 同じ数。

## 3. 画面や Discord から動く処理

| きっかけ | 処理 | D1 読み取り | D1 書き込み |
|---|---|---|---|
| サイトを開く・更新を押す | 同期状況の取得（`/api/status`）。試合数や取り込み待ちを数え直す | 約5,900行／回 | なし |
| プレイヤーのページを開く | 戦績の集計。開いた人の新着確認と取り込み（2試合） | その人の試合数ぶん | 取り込みがあれば46行／試合 |
| チーム分けタブを開く・分ける | 登録者のレート計算、最近のマップ | 約9,000行／回＋1人あたり約200行 | なし |
| チーム分けに人を追加（ウェブ／`/link`） | アカウント検索、ランク・RR・直近10試合の履歴を取得（API の枠を7消費） | 少量 | 数行＋試合1件につき約4行 |
| 追加後、取り込みが終わるまで | チーム分けタブが15秒おきに同期状況を取得 | 約5,900行／回 | なし |

## 4. データの置き場と保持期間

| D1 のテーブル | 中身 | 1件の大きさ | いつ消えるか |
|---|---|---|---|
| `matches` | 試合の基本情報と、ラウンドごとの記録（キル・設置・装備） | 約10KB | 収集対象だけの試合は14日後。それ以外は消えない |
| `player_matches` | 1試合10人ぶんの成績（約45項目） | 10行で約6KB | 同上 |
| `match_raw` | 本人の試合の生データ（gzip）。コンペ・アンレート・Premier・スイフトプレイ・5vs5 カスタムのみ | 約30KB | 消えない |
| `match_queue` | 取り込み待ちと取り込み済みの記録（同じ試合を取り直さないため） | 約0.2KB | 消えない |
| `mmr_history` | 本人の RR の履歴 | 小 | 消えない |
| `players` / `discord_links` / `tracked` | 本人・検索された人 / チーム分けの登録者 / 収集対象 | 小 | 手動で消すまで |
| `lobbies` / `lobby_members` / `meta` | Discord の募集 / 各種の時刻や設定 | 小 | 消えない |

R2 に置いたもの（試合の集計の写し、日ごとの控え、分析側が集めた試合）は消さない。1試合約30KBで、1日約7MBずつ増える。

## 5. D1 の使用量と見通し

### 容量（上限 500MB）

| 項目 | 現在 | 落ち着く先 |
|---|---|---|
| 収集対象だけの試合（14日ぶん） | 約38MB（2,216試合） | 約55MB（1日220試合 × 14日） |
| 消さない試合（本人など）と生データ | 約9MB | 月に3〜5MBずつ増える（本人のプレイ量しだい） |
| 合計 | 47.5MB | 約65〜70MB（12月初めに頭打ち）。その後は年に40〜60MB増 |

- いま増えているのは、収集を始めてまだ14日たっておらず、削除が始まっていないため。最初に取り込んだ試合が14日を過ぎる12月初めから、取り込みと削除が釣り合う。
- 収集対象は自動で400人まで増える設計。上限まで増えると、14日ぶんは約160MBになる。

### 書き込み（上限 1日10万行）

| 処理 | 1日あたり | 割合 |
|---|---|---|
| 本人アカウントの RR 履歴の上書き | 約20,000行 | 54% |
| 試合の取り込み（240試合 × 46行） | 約11,000行 | 30% |
| 古い試合の削除（220試合 × 11行。12月から） | 約2,400行 | 6% |
| 収集対象の確認時刻、取り込み待ちへの追加 | 約2,200行 | 6% |
| 同期時刻、保管庫の印、その他 | 約1,500行 | 4% |
| 合計 | 約37,000行 | 上限の37% |

- 取り込みが上限（1日576試合）で続いた日は約53,000行。初日・2日目（752試合・1,047試合を取り込んだ日）がこれに近い。
- 10人を一度に登録すると、最大100試合で約4,600行が上乗せされる。

### 読み取り（上限 1日500万行）

| 処理 | 1日あたり |
|---|---|
| 古い試合の削除の候補探し（4,200行 × 24回） | 約100,000行 |
| 通常の同期（約250行 × 288回） | 約72,000行 |
| 本人アカウントの確認 | 約30,000行 |
| 毎分の確認、試合の取り込み | 約7,000行 |
| 合計（人が何もしなくても動くぶん） | 約210,000行（上限の4%） |

人の操作で増えるぶん: 同期状況の取得が1回約5,900行、チーム分けが1回約9,000行。
10人登録後の取り込み待ち（約10分）のあいだ、チーム分けタブを開いたままだと約24万行。

## 6. 上限に近づく条件と、減らせる箇所

いまの使い方では、容量・書き込み・読み取りのどれも上限には届かない見込み。近づくのは次の場合。

| 上限 | 近づく条件 |
|---|---|
| 書き込み 1日10万行 | 取り込みが1日1,000試合を超える（収集対象を大きく増やす、取り込み間隔を詰める） |
| 容量 500MB | 収集対象が400人を大きく超える、保持期間を延ばす、本人アカウントの生データが数千試合たまる |
| 読み取り 1日500万行 | 同期状況の取得を短い間隔で長時間続ける（1日850回で上限） |

減らせる箇所（効果の大きい順）:

1. **RR 履歴の上書きをやめ、新しい行だけ書く** — 書き込みが1日約2万行減る（全体の半分）。機能は変わらない。
2. **収集対象だけの試合は、ラウンドごとの記録を D1 に置かない** — 1試合17KB → 約7KB。14日ぶんの容量が約55MB → 約23MB になる。記録は R2 に残る。
3. **保持期間を14日から7日にする** — 14日ぶんの容量が半分になる。レートの計算には影響しない（収集対象はレート計算に使っていない）。
4. **同期状況の数え方を軽くする** — 1回約5,900行 → 数十行。
5. **古い試合の削除と、最近の試合の検索に索引を足す** — 読み取りが1日約10万行減る。チーム分けも1回約9,000行 → 数百行になる。

## 7. 主な設定値

| 設定 | 値 | 場所 |
|---|---|---|
| 定期実行の間隔 | 毎分（通常の同期は5分ごと） | `wrangler.jsonc`、`src/index.ts` |
| 通常の同期で取り込む試合数 | 2試合／回 | `src/index.ts` |
| 急ぎの取り込み | 1回の定期実行で最長50秒、登録後20秒は待つ | `src/index.ts` |
| 本人アカウントの確認 | 最大3つ／回、5分以上あける | `src/sync.ts` |
| 収集対象の確認 | 2人／回、同じ人は3時間以上あける、上限400人 | `src/sync.ts` |
| 収集対象だけの試合の保持 | 14日（1時間に最大40試合を削除） | `src/sync.ts` |
| 保管庫への書き出し | 20試合／回 | `src/sync.ts` |
| 生データの圧縮 | 2件／回（取り込みがなかった回だけ） | `src/sync.ts` |
| 登録時に積む試合 | 直近10試合（コンペ・アンレート・Premier） | `src/roster.ts` |
| 生データを残すモード | コンペ・アンレート・Premier・スイフトプレイ・5vs5 カスタム（本人のみ） | `src/db.ts` |
